# ADR 0006 — Mode-3 substrate re-scope vs native platform primitives

**Status:** Accepted (analysis + decision; retirement gated on one pilot)
**Date:** 2026-07-19
**Deciders:** Markandey (with Claude)

## Context

Mode 3 (`/orchestrate-loops`) ships a custom durable-loop substrate:
`tasks.json` (generated by `tasks-sync.sh` from TASKS.md) + per-leaf
worktrees + `guard-file-domain.sh` (PreToolUse write-scoping) + attempt caps.
Since it was designed, the platform has shipped: background subagents by
default with Monitor/ScheduleWakeup, experimental Agent Teams with a native
shared task list, and native TaskCreate/TaskList/TaskUpdate primitives.
ADR 0001 already moved *static* task lists to `Workflow()`; the custom
substrate remains only for dynamic mid-run decomposition.

## Decision

1. **Keep `guard-file-domain.sh`.** Nothing native enforces per-leaf write
   scoping at the hook layer; it is cheap (no-op unless `LEAF_DOMAIN_GLOBS`
   set) and is the safety property of Mode 3.
2. **Keep worktree isolation + attempt caps** — native background agents
   provide worktrees but not attempt-capped retry semantics.
3. **Mark `tasks.json` + `tasks-sync.sh` as retirement candidates.** Native
   task primitives (TaskCreate/List/Update with owners and dependencies)
   cover the substrate's queue role. Plan: run ONE real phase on the native
   task list driven by `/orchestrate-loops`; if leaf claiming, progress
   tracking, and crash recovery hold, delete `tasks-sync.sh` and the
   `tasks.json` format in the following minor version.
4. **Agent Teams stays out of Mode 3** until it leaves experimental status
   (verified still flag-gated on CLI 2.1.214, 2026-07-18); Mode 2
   (`/start-phase-team`) remains its home.

## Consequences

- No code deleted today — the ADR records what must be true before deletion
  (the pilot), preventing both premature removal and silent drift.
- The kit keeps one honest differentiator (file-domain write enforcement)
  and sheds queue plumbing as soon as the native path proves out.
