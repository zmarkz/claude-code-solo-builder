# Claude Code Settings, Themes, and Hooks

> How to configure Claude Code for maximum productivity and safety.

---

## Global Settings (`~/.claude/settings.json`)

The recommended global settings:

```json
{
  "model": "sonnet",
  "effortLevel": "xhigh",
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  },
  "tui": "fullscreen",
  "skipDangerousModePermissionPrompt": true,
  "theme": "dark",
  "preferredNotifChannel": "ghostty",
  "remoteControlAtStartup": true,
  "agentPushNotifEnabled": true,
  "enabledPlugins": {
    "claude-md-management@claude-plugins-official": true
  }
}
```

### Key settings explained

| Setting | Value | Why |
|---------|-------|-----|
| `model` | `"sonnet"` | Sonnet 4.6 is a fine cost baseline — but see the note below: with **Opus 4.8 fast mode**, `"opus"` is now viable as the daily driver. Downgrade to haiku for repetitive tasks |
| `effortLevel` | `"xhigh"` | Maximum reasoning depth. Worth the cost for real work. |
| `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` | `"1"` | Enables `/start-phase-team` parallel agent teams (requires Claude Code v2.1.32+) |

### Model choice under Opus 4.8 + fast mode

The old advice — "Sonnet baseline, upgrade to Opus only for planning" — assumed Opus was the slow,
expensive tier. **Opus 4.8 fast mode** (toggle with `/fast`) delivers Opus-class reasoning at much
higher throughput *without* downgrading the model, which changes the default:

- **Daily driver / interactive / planning / review** → `"opus"` with `/fast` on. You no longer eat a
  latency penalty for Opus judgment, so there's little reason to sit on Sonnet for hands-on work.
- **Wide parallel fan-outs (Mode 3 leaves)** → keep most leaves on Sonnet 4.6 for token economy;
  promote judgment-heavy slices (auth, money, schema) to Opus 4.8.
- **Repetitive grind** → Haiku 4.5 / local Qwen, unchanged.

Fast mode is a runtime toggle, not a `settings.json` key — `/fast` flips it per session (supported on
Opus 4.8/4.7/4.6). See `docs/TOKEN-EFFICIENCY.md` › *Strategy 2* for model-routing guidance.
| `tui` | `"fullscreen"` | Full terminal UI — better for long sessions than inline mode |
| `theme` | `"dark"` | Dark theme — reduces eye strain in long sessions |
| `preferredNotifChannel` | `"ghostty"` | Ghostty terminal for notifications. Change to `"iterm"` or `"terminal"` for your setup |
| `remoteControlAtStartup` | `true` | Enables remote control for mobile workflows (Tailscale + SSH) |
| `agentPushNotifEnabled` | `true` | Push notifications when background agents complete |

## Per-Machine Settings (`~/.claude/settings.local.json`)

Machine-specific permissions that don't belong in the global config:

```json
{
  "autoUpdatesChannel": "latest",
  "permissions": {
    "allow": [
      "WebFetch(domain:docs.stripe.com)",
      "WebFetch(domain:supabase.com)",
      "Bash(docker:*)",
      "Bash(git:*)",
      "Bash(pnpm:*)",
      "Bash(npm:*)"
    ],
    "deny": [],
    "ask": [
      "Bash(rm -rf:*)",
      "Bash(git push --force:*)"
    ]
  }
}
```

### Permission layers: deny / ask / allow

```
deny  → Always blocked, no prompt
ask   → Prompted every time (dangerous but occasionally needed)
allow → Pre-approved, no prompt
```

**Default deny (recommended):**
- `rm -rf` on important paths
- Force push to main/master
- Any command modifying `~/.ssh`, `~/.aws`, `~/.gnupg`
- Secrets store modifications

**Default allow (add these for smooth workflow):**
- `git status`, `git diff`, `git log` (read-only)
- `pnpm install`, `npm install`
- `docker ps`, `docker logs`
- `cat`, `ls`, `find`, `grep`
- `WebFetch` for your approved domains (docs, APIs)

## Hooks — The 6 Guardrail Scripts

Hooks run on specific Claude Code events. They are safety guards, not clever automation.

**Rule: hooks should fail loudly and early. Never make hooks do clever things.**

### 1. `session-start.sh` (SessionStart)

Runs at the start of every session:
```bash
#!/bin/bash
# Verify we're in the right directory
# Check active phase from ROADMAP.md
# Report open tasks from TASKS.md
# Warn if CLAUDE.md is > 200 lines
```

Output example:
```
=== Session Start ===
Project: my-app | Phase: 1 | Branch: feat/auth
Open tasks: 3
CLAUDE.md: 147 lines (OK)
```

### 2. `guard-dangerous-command.sh` (PreToolUse: Bash)

Checks every bash command before execution:
```bash
#!/bin/bash
COMMAND="$1"
DANGEROUS_PATTERNS=(
  "rm -rf /"
  "curl .* | bash"
  "wget .* | sh"
  "eval "
  "git push --force origin main"
)
# Exits non-zero if any pattern matches → blocks the command
```

### 3. `check-secrets-staged.sh` (PreToolUse: Write)

Before any file write, scans for secrets:
```bash
#!/bin/bash
FILE="$1"
# Checks for: API keys, passwords, tokens, private keys
# Patterns: AKIA*, sk-*, ghp_*, password=, secret=
# Exits non-zero → blocks the write if secrets detected
```

### 4. `secret-scan.sh` (Manual / CI)

Full repo secret scan (run by pre-commit):
```bash
#!/bin/bash
# Uses gitleaks or equivalent
# Scans entire git history, not just current files
# Run: bash scripts/secret-scan.sh
```

### 5. `run-quality-checks.sh` (PostToolUse: Write)

After any file write, runs quality checks:
```bash
#!/bin/bash
FILE="$1"
EXTENSION="${FILE##*.}"
# TypeScript: tsc --noEmit for .ts/.tsx files
# Python: flake8/mypy for .py files
# Non-zero exit → surfaces the error (doesn't block, just informs)
```

### 6. `session-snapshot.sh` (PreCompact)

Before context compaction, saves state:
```bash
#!/bin/bash
SNAPSHOT_DIR="docs/session-snapshots"
mkdir -p "$SNAPSHOT_DIR"
SNAPSHOT_FILE="$SNAPSHOT_DIR/$(date +%Y%m%d-%H%M%S).md"

{
  echo "# Session Snapshot — $(date)"
  echo ""
  echo "## Git State"
  git status
  echo ""
  echo "## Recent Commits"
  git log --oneline -10
  echo ""
  echo "## Open Tasks"
  grep '^\- \[ \]' TASKS.md 2>/dev/null | head -10
} > "$SNAPSHOT_FILE"
```

## Themes

### Dark theme (recommended)
```json
{ "theme": "dark" }
```

Claude Code's dark theme uses a high-contrast palette optimized for long sessions.

### Custom terminal theme

For the full dark experience, also configure your terminal:

**Ghostty:**
```
theme = catppuccin-mocha
background = #1e1e2e
foreground = #cdd6f4
```

**iTerm2:** Import the Catppuccin Mocha theme from the catppuccin/iterm project.

**VS Code (Claude Code sidebar):** Install the "Catppuccin Mocha" theme.

## Notification Channels

Set `preferredNotifChannel` to your terminal emulator:

| Terminal | Value |
|---------|-------|
| Ghostty | `"ghostty"` |
| iTerm2 | `"iterm"` |
| macOS Terminal | `"terminal"` |
| WezTerm | `"wezterm"` |

Agent push notifications (`agentPushNotifEnabled: true`) alert you when background agents complete — useful when you start a `/build-phase-autopilot` run and walk away.

## Plugins

### claude-md-management (recommended)

```json
{
  "enabledPlugins": {
    "claude-md-management@claude-plugins-official": true
  }
}
```

Adds `/revise-claude-md` and `/claude-md-improver` commands that help maintain CLAUDE.md under the 200-line cap. Run these when CLAUDE.md starts feeling bloated.

### Plugin hygiene

- Cap at 3-5 active plugins total
- Review plugin permissions before enabling
- Prefer official plugins over community ones
- Avoid plugins that require broad filesystem or network access

## The Settings Hierarchy

```
~/.claude/settings.json              ← Global (all projects)
~/.claude/settings.local.json        ← Machine-specific permissions
<project>/.claude/settings.json      ← Project-specific (overrides global)
```

Project settings win for permissions. Global settings win for UI preferences.
